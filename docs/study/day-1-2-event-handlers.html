ימים 1–2 — מיפוי כל on_* event handler

קוראים את server/app.py מלמעלה למטה. המטרה לכל handler: "ה-client שולח (emit) את event X ← הפונקציה הזו רצה ← הדברים האלה קורים."

כל הקובץ הוא Socket.IO event router. הדפדפן (עמוד ה-host או עמוד ה-player) שולח events בעלי שם דרך websocket; כל פונקציית @socketio.on('name') היא התגובה של השרת. אין request/response — השרת דוחף מצב חזרה החוצה עם socketio.emit(...) / emit(...) בכל פעם שמשהו משתנה.
ה-handlers בעמוד הזה on_connect — socket נפתח on_disconnect — socket נסגר on_host_connected — מסך ה-host נטען on_join_game — שחקן לוחץ "Join" on_add_bot / on_remove_bot — כפתורי הבוטים בלובי on_start_game — ה-host לוחץ "Start" on_player_action — שחקן לוחץ Fold/Call/Raise on_restart_game / on_pause_game on_next_hand — ה-host לוחץ "Next hand"

ה-state המשותף שכולם משנים

לפני ה-handlers, חמישה dicts/lists ברמת המודול מחזיקים את כל עולם הפוקר (app.py:33–40). תחזיק אותם בראש — כל handler נוגע בחלק מהם.

MAX_PLAYERS = 8
session_players  = {}   # session_id -> {nickname, chips, sid, is_connected, state, is_bot?, personality?}
sid_to_session   = {}    # socket id  -> session_id      (reverse lookup: "מי שלח את זה?")
current_game     = None  # אובייקט ה-Game החי, או None כשאנחנו בלובי
session_to_player = {}   # session_id -> Player object    (קיים רק כשמשחק רץ)
game_active      = False # True בין start_game לסיום המשחק
join_queue      = []    # session_ids שמחכים להיכנס למשחק שרץ
שני מזהים, ולמה. session_id נוצר על ידי הדפדפן ונשמר ב-localStorage שלו — הוא שורד רענון עמוד. sid הוא ה-Socket.IO connection id — הוא חדש בכל פעם שה-socket מתחבר מחדש. השרת שומר את הדאטה האמיתי לפי session_id ומתייחס ל-sid כאל "הצינור הנוכחי לאדם הזה" שאפשר לזרוק. ה-indirection הזה הוא מה שגורם ל-reconnect לעבוד (שבוע 2).

2. on_disconnect

client emits: "disconnect" (אוטומטי — טאב נסגר, רענון, נפילת רשת) 
@socketio.on('disconnect')
def on_disconnect():
    sid = _request_sid()

    # ---- Poker ----
    session_id = sid_to_session.pop(sid, None)          # 1
    if session_id:
        info = session_players.get(session_id)
        if info:
            info['sid'] = None                          # 2
            info['is_connected'] = False
            player = session_to_player.get(session_id)
            if player:
                player.sid = None                       # 3
                player.is_connected = False
            _broadcast_lobby()                           # 4
            _broadcast_queue()
            if current_game:
                if not _finish_game_if_too_few_connected():   # 5
                    _process_automatic_turns()                # 6
                    _broadcast_game_state()

    # ---- Blackjack ---- (אותה צורה, maps של bj_*)
    ...
  1. שוכחים את הצינור. pop מוחק את הקישור sid → session_id ומחזיר לנו את ה-session_id שהוא הצביע עליו (או None אם ה-socket הזה אף פעם לא היה שחקן פוקר — למשל ה-host, או שחקן blackjack).
  2. מסמנים את האדם כ-offline ב-session_players אבל שומרים את הרשומה — הכינוי, הצ'יפים והמושב שלו עדיין שמורים ל-reconnect.
  3. משקפים את זה על אובייקט ה-Player החי אם משחק רץ, כדי שה-engine ידע שהמושב הזה עכשיו "connected: false".
  4. מודיעים לכולם שהלובי / ה-queue השתנו (הנקודה של השחקן הזה הופכת אפורה).
  5. אם נשארו מעט מדי בני אדם, _finish_game_if_too_few_connected() מסיים את היד ומחזיר True — עוצרים כאן.
  6. אחרת ממשיכים את המשחק. ייתכן שהשחקן שהתנתק היה זה שאמור לפעול; _process_automatic_turns() יעשה auto-fold/check עבורו כדי שהשולחן לא ייתקע, ואז נשדר את המצב החדש. (פירוט מלא בימים 3–4.)
הרעיון המרכזי: disconnect אף פעם לא מוחק שחקן. הוא מוריד אותו לדרגת "מושב שמור, offline". כל ה-reconnect תלוי בזה.

3. on_host_connected

client emits: "host_connected" (עמוד ה-projector /host, בטעינה) 
@socketio.on('host_connected')
def on_host_connected():
    emit('lobby_update', _lobby_snapshot())     # השחקנים היושבים כרגע
    emit('queue_update', _queue_snapshot())     # שחקנים שמחכים
    if current_game:
        emit('game_starting', {})               # אומרים ל-host לעבור ל-view של השולחן
        emit('game_state', current_game.to_dict())   # מצב משחק ציבורי מלא

זה handler של catch-up. emit() (בלי to=) שולח רק ל-socket ששאל. אם מסך ה-host נטען מחדש באמצע משחק, ארבע השורות האלה בונות מחדש את כל ה-view שלו מאפס. שים לב שה-host מקבל את current_game.to_dict() בלי קלפי hole — מסך ה-host הוא ציבורי.

Helpers שה-handler הזה נשען עליהם

def _attach_session_to_sid(session_id, sid):
    info = session_players[session_id]
    old_sid = info.get('sid')
    if old_sid and old_sid != sid:
        sid_to_session.pop(old_sid, None)   # זורקים את מיפוי ה-socket הישן
    sid_to_session[sid] = session_id
    info['sid'] = sid
    info['is_connected'] = True

def _sync_player_connection(session_id):    # דוחפים info -> אובייקט Player חי
    player = session_to_player.get(session_id)
    info   = session_players.get(session_id)
    if player and info:
        player.sid = info['sid']
        player.is_connected = info['is_connected']

5. on_add_bot ו-on_remove_bot

@socketio.on('add_bot')
def on_add_bot(data):
    if game_active:
        emit('add_bot_error', {'message': 'Can only add bots before the game starts.'}); return
    if _lobby_seat_count() >= MAX_PLAYERS:
        emit('add_bot_error', {'message': f'Table is full (max {MAX_PLAYERS}).'}); return

    personality = ((data or {}).get('personality') or 'calculator').strip().lower()
    if personality not in {'calculator', 'rock', 'maniac'}:
        personality = 'calculator'

    bot_session_id = _random_id('bot')
    while bot_session_id in session_players:      # מבטיחים ייחודיות
        bot_session_id = _random_id('bot')

    session_players[bot_session_id] = {
        'session_id': bot_session_id, 'nickname': _unique_bot_nickname(personality),
        'chips': 1000, 'sid': None, 'is_connected': True,   # בוטים הם "תמיד מחוברים"
        'state': 'lobby', 'is_bot': True, 'personality': personality,
    }
    _broadcast_lobby()

בוט הוא סתם עוד רשומה ב-session_players עם is_bot: True, is_connected: True (הוא אף פעם לא נופל) ובלי sid (אין למי לשלוח). on_remove_bot הוא המראה: מוצאים את הרשומה עם nickname תואם ו-is_bot, עושים pop, משדרים מחדש. שניהם lobby-only — חסומים ברגע ש-game_active.

6. on_start_game

client emits: "start_game" (ה-host לוחץ "Start") 
@socketio.on('start_game')
def on_start_game():
    global current_game, session_to_player, game_active

    eligible = _eligible_start_players()          # בוטים + בני אדם מחוברים בלובי
    if len(eligible) < 2:
        emit('start_error', {'message': 'Need at least 2 connected players to start.'}); return

    players = []
    session_to_player = {}
    for session_id, info in session_players.items():
        if info['state'] != 'lobby': continue
        if not info.get('is_bot') and not info.get('is_connected'): continue   # מדלגים על בני אדם offline
        if len(players) >= MAX_PLAYERS: continue
        info['state'] = 'game'
        if info.get('is_bot'):
            player = BotPlayer(info['nickname'], info.get('personality') or 'calculator', info['chips'])
            player.session_id = session_id
            player.is_connected = True
        else:
            player = HumanPlayer(info['nickname'], session_id, info['sid'], info['chips'])
            player.is_connected = info['is_connected']
        players.append(player)
        session_to_player[session_id] = player

    current_game = Game(players)       # engine של היד משתלט
    game_active = True
    current_game.start_hand()          # מערבבים, שמים blinds, מחלקים קלפי hole

    socketio.emit('game_starting', {})          # כל מסך עובר לשולחן
    _broadcast_lobby()
    _broadcast_game_state()                      # מצב ציבורי לכולם
    _send_private_hands()                        # קלפי hole, socket אחד לכל שחקן
    _process_automatic_turns()                   # אם הראשון לפעול הוא בוט, מפעילים אותו
  1. בונה את המפה session_to_player (מאוכלסת רק בזמן משחק).
  2. הופך כל רשומת לובי לאובייקט BotPlayer / HumanPlayer אמיתי ומעביר את ה-state שלו ל-'game'.
  3. בונה את ה-Game וקורא ל-start_hand() — מכאן game_engine.py אחראי על סדר התורות, ה-pot וה-streets.
  4. ארבעה emits: game_starting (מעבר view) ← game_state (ציבורי) ← your_hand לכל שחקן (פרטי) ← auto-turns.

7. on_player_action

client emits: "player_action" {action, amount} (Fold / Check / Call / Raise) 
@socketio.on('player_action')
def on_player_action(data):
    if not current_game or not game_active:
        return
    action = data.get('action', '')
    amount = int(data.get('amount', 0))
    _apply_and_advance(_request_sid(), action, amount)

קטן בכוונה — הוא רק מגן, ממיר טיפוסים, ומעביר הלאה. כל ה-lifecycle של emit → validate → mutate → broadcast חי ב-_apply_and_advance, שהוא כל הנושא של ימים 3–4. להיום רק דע: זו נקודת הכניסה למהלך של אדם.

8. on_restart_game ו-on_pause_game

client emits: "restart_game" / "pause_game" (בקרות ה-host) 
@socketio.on('restart_game')
def on_restart_game():
    if not current_game and not game_active: return
    socketio.emit('game_finished', {'winner': None, 'restarted': True})
    for info in session_players.values():
        info['chips'] = 1000                 # כולם חוזרים ל-buy-in
    _db_reset_chips('poker', 1000)            # no-op
    _end_game_session()

@socketio.on('pause_game')
def on_pause_game():
    if not current_game and not game_active: return
    socketio.emit('game_paused', {})
    _end_game_session()

אותו teardown, טיפול שונה בצ'יפים. Restart מאפס צ'יפים ל-1000; pause שומר אותם. שניהם קוראים ל:

def _end_game_session():
    global current_game, session_to_player, game_active, join_queue
    game_active = False
    current_game = None
    session_to_player = {}
    join_queue = []
    for info in session_players.values():
        info['state'] = 'lobby'          # כולם חוזרים ללובי
    _broadcast_queue(); _broadcast_lobby()

אחרי זה העולם נראה כמו שנראה לפני start_game, חוץ מזה שהצ'יפים עשויים להיות שונים ואנשים אולי התנתקו.

9. on_next_hand

client emits: "next_hand" (ה-host לוחץ "Next hand" אחרי showdown) 
@socketio.on('next_hand')
def on_next_hand():
    if not current_game:
        return
    _flush_queue()                              # 1: מושיבים כל מי שהצטרף במהלך היד הקודמת
    if _finish_game_if_too_few_connected():      # 2: יוצאים אם נשארו מעט מדי שחקנים
        return
    current_game.next_hand()                     # 3: מזיזים את ה-dealer button, מערבבים מחדש, מחלקים
    _sync_all_game_player_chips()                # 4: מעתיקים ספירת צ'יפים מה-engine ל-session_players
    _broadcast_game_state()                      # 5: מצב ציבורי
    _send_private_hands()                        # 6: קלפי hole חדשים
    _process_automatic_turns()                   # 7: בוט / offline משחק אוטומטית אם ראשון לפעול
  1. _flush_queue() עובר על join_queue, ולכל ממתין שעדיין מחובר ויש לו מקום בשולחן, בונה HumanPlayer, מוסיף אותו ל-current_game.players, ושולח לו game_starting. כל מי שאי אפשר להושיב (שולחן מלא, או עכשיו offline) נשאר ב-queue.
  2. אם שחקנים פשטו רגל או נפלו ונשארו פחות מ-2, מסיימים את המשחק.
  3. ה-engine מחלק את היד הבאה.
  4. _sync_all_game_player_chips() — ה-engine הוא ה-source of truth לצ'יפים במהלך יד; זה דוחף אותם חזרה ל-session_players כדי שה-snapshots של הלובי / ה-queue יישארו מדויקים.
  5. –7. אותה שלישיית broadcast כמו ב-start_game.

בדיקה עצמית לפני ימים 3–4

כסה את התשובות ואמור כל אחת בקול:

  1. Client שולח join_game עבור session_id שכבר קיים ב-session_players באמצע יד ← נתיב reconnect: קישור מחדש של ה-sid, replay של המצב כולל קלפי hole, broadcast מחדש. בלי מושב חדש.
  2. Client שולח disconnect ונשאר רק אדם 1 ביד ← _finish_game_if_too_few_connected() שולח game_finished, _end_game_session() מאפס ללובי.
  3. למה on_player_action הוא רק 6 שורות? זו רק נקודת הכניסה של ה-socket; העבודה האמיתית היא _apply_and_advance (ימים 3–4).
  4. מה state ('lobby' / 'queued' / 'game') שולט עליו? מי נחשב כמושב, מי הופך ל-Player ב-start_game, את מי _flush_queue מושיב.
  5. ההבדל בין sid ל-session_id? sid = per-connection, משתנה ברענון; session_id = per-browser, קבוע. הדאטה נשמר לפי session_id.
emit → this handler runs → mutate the shared dicts → socketio.emit(...) pushes new state to the screens
