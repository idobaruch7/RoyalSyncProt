ימים 6–7 — ה-blackjack mirror

המטרה היא לא ללמוד את הבלאקג'ק מאפס — אלא לאשר שהוא אותה תבנית: כל bj_* הוא בן־דוד של פונקציית פוקר שכבר קראת. אם אתה מזהה את הצורה, סיימת.

Flask process אחד מריץ שני מופעי משחק במקביל. הבלאקג'ק הוא עותק שני של אותו רעיון עם prefix bj_ על כל שם: אותם maps, אותו emit → validate → mutate → broadcast, אותו סיפור reconnect/queue.

2. _bj_apply_action — אותו "מנצח", קצר יותר

def _bj_apply_action(session_id, action):
    if not bj_current_game:
        return

    event = bj_current_game.apply_action(session_id, action)   # validate + mutate
    _bj_sync_chips()                                           # engine chips -> bj_session_players
    _bj_broadcast_state()                                      # broadcast ציבורי לכולם

    if event == 'dealer_turn':                                 # כל השחקנים סיימו -> תור הדילר
        _bj_schedule_dealer_sequence()
    elif event == 'continue':                                  # עוד שחקנים לפעול
        _bj_process_auto_turns()

שים אותו ליד _apply_and_advance: אותו רצף בדיוק — apply → sync chips → broadcast → הסתעפות לפי ה-event. פשוט יותר כי בבלאקג'ק אין action_event toast ואין not_your_turn מטופל בנפרד (ה-engine מחזיר אותו, וכאן פשוט לא נכנסים לאף branch).

ה-engine: BlackjackGame.apply_action (blackjack_engine.py:76)

def apply_action(self, session_id, action):
    if not self.to_act or self.to_act[0] != session_id:
        return 'not_your_turn'                        # אותה בדיקת בעלות כמו בפוקר
    state = self.player_states.get(session_id)
    if not state or state['status'] != 'playing':
        return 'invalid'

    if action == 'stand':
        state['status'] = 'standing'; self.to_act.pop(0)
    elif action == 'hit':
        state['cards'].extend(self.deck.deal(1))
        val = hand_value(state['cards'])
        if val > 21:   state['status'] = 'bust';     self.to_act.pop(0)
        elif val == 21: state['status'] = 'standing'; self.to_act.pop(0)
        # else: נשאר 'playing' - אפשר לפעול שוב
    elif action == 'double':
        ... מכפילים bet, קלף אחד, תמיד יוצאים מהתור ...
        self.to_act.pop(0)
    else:
        return 'invalid'

    if not self.to_act:                # ה-to_act queue התרוקן
        self.state = 'dealer_turn'
        return 'dealer_turn'
    return 'continue'
אותו to_act queue כמו בפוקר. כל פעולה עושה pop(0) (חוץ מ-hit שלא פוצץ ולא הגיע ל-21 — מקביל ל-full raise שמשאיר אותך בתור). כשהתור מתרוקן, השלב מתקדם — כאן ל-'dealer_turn' במקום street חדש.

3. _bj_process_auto_turns — מקביל ל-_process_automatic_turns

def _bj_process_auto_turns():
    while bj_current_game and bj_current_game.state == 'player_turns':
        player = bj_current_game.current_player()
        if player is None:
            return
        if not getattr(player, 'is_connected', True):        # שחקן offline
            event = bj_current_game.apply_action(player.session_id, 'stand')   # ברירת מחדל: stand
            _bj_sync_chips(); _bj_broadcast_state()
            if event == 'dealer_turn':
                _bj_schedule_dealer_sequence(); return
            continue
        _bj_notify_current_player()                          # אדם מחובר -> prompt, מחכים
        return

קצר יותר מגרסת הפוקר כי אין בוטים — אין ענף isinstance(player, BotPlayer). נשארו שני מקרים: אדם מחובר (prompt) או offline (auto-stand, שקול ל-auto-check של פוקר).

4. רצף הדילר — מקביל ל-bot turn, אבל דטרמיניסטי

אותה תבנית: _bj_dealer_pending mutex + background task + socketio.sleep 
_bj_dealer_pending = False

def _bj_schedule_dealer_sequence():
    global _bj_dealer_pending
    if _bj_dealer_pending:                       # כמו _bot_action_pending: לא לערום שני רצפים
        return
    _bj_dealer_pending = True
    socketio.start_background_task(_bj_run_dealer_sequence)

def _bj_run_dealer_sequence():
    global _bj_dealer_pending
    game = bj_current_game
    try:
        if not game or game.state != 'dealer_turn':
            return
        _bj_broadcast_state()                    # קלף hole עדיין face-down
        socketio.sleep(1.5)
        if bj_current_game is not game:          # המשחק התאפס בזמן ה-sleep -> נטוש
            return
        game.dealer_reveal()
        _bj_broadcast_state()                    # קלף ה-hole מתהפך face-up

        while game.dealer_needs_hit():           # חוקי בית: hit עד 17
            if bj_current_game is not game: return
            socketio.sleep(1.5)
            if bj_current_game is not game: return
            game.dealer_hit()
            game.dealer_reveal_next()
            _bj_broadcast_state()               # קלף חדש כבר face-up

        if bj_current_game is not game: return
        game.finish_round()                      # מחשבים תוצאות, משלמים
        _bj_sync_chips()
        _bj_broadcast_state()
        _bj_emit_round_over()                    # מקביל ל-_broadcast_hand_over של פוקר
    finally:
        _bj_dealer_pending = False               # תמיד מנקים, גם על exception
  • אותם שלושה מנגנוני בטיחות כמו _run_bot_turn: guard בוליאני, בדיקת bj_current_game is not game אחרי כל sleep, וניקוי ה-guard ב-finally.
  • ההבדל: הבוט מקבל החלטה מ-player.get_action(...); הדילר משחק לפי חוק קבוע (dealer_needs_hit → hit עד 17). דטרמיניסטי, לא AI.
  • ה-socketio.sleep(1.5) בין קלפים הוא לצורך דרמה על מסך ה-host. משתמשים ב-socketio.sleep ולא ב-time.sleep כי הוא async-mode-aware (עושה את הדבר הנכון תחת threading / eventlet / gevent), והוא רץ ב-background task נפרד כך שה-handler שהתחיל אותו כבר חזר.

def _bj_notify_current_player():
    player = bj_current_game.current_player()
    if player is None or not getattr(player, 'sid', None):
        return
    state = bj_current_game.player_states.get(player.session_id, {})
    cards = state.get('cards', [])
    val = bj_hand_value(cards) if cards else 0
    can_double = len(cards) == 2 and player.chips > 0
    socketio.emit('bj_your_turn', {'hand_value': val, 'can_double': can_double}, to=player.sid)

אותה צורה כמו _notify_current_player: ל-socket אחד, עם המידע שהשרת חישב לגבי הפעולות החוקיות (כאן: האם double אפשרי).

בדיקה עצמית

  1. למה בבלאקג'ק אין to_dict(for_sid)? אין מידע פרטי בין שחקנים; רק קלף ה-hole של הדילר מוסתר, ומכולם, דרך {'rank':'?'}.
  2. מה מקביל ל-_bot_action_pending? _bj_dealer_pending — אותו mutex שמונע שני dealer sequences במקביל.
  3. מה מקביל ל-full raise שמשאיר אותך בתור? hit שלא פוצץ ולא הגיע ל-21 — לא עושה to_act.pop.
  4. למה _bj_process_auto_turns קצר יותר? אין בוטים, אז אין ענף BotPlayer — רק אדם מחובר או offline.
  5. איך תהליך Flask אחד מריץ שני משחקים? שתי קבוצות משתני מודול נפרדות (poker / bj_), אותם handlers עם prefix, אותו socketio server. הרצפים הארוכים (bot / dealer) רצים כ-background tasks דרך socketio.start_background_task כדי שה-handlers יחזרו מיד.
"בלאקג'ק הוא ה-mirror: כל bj_* הוא אותה פונקציה עם prefix. on_bj_player_action → _bj_apply_action עושה apply → sync chips → broadcast → הסתעפות לפי event, בדיוק כמו _apply_and_advance. ה-dealer sequence הוא ה-bot turn בגרסה דטרמיניסטית, עם אותו _pending mutex ו-socketio.sleep. ההבדל היחיד המהותי: אין state פרטי בין שחקנים, אז יש רק to_dict() אחד ו-broadcast ציבורי אחד."
